# Публикация и демонстрация «СОБРАНО»

Репозиторий: https://github.com/china1602-glitch/sobrano

Адрес Pages: https://china1602-glitch.github.io/sobrano/

Развёртывания: https://github.com/china1602-glitch/sobrano/actions

Настройки: https://github.com/china1602-glitch/sobrano/settings/pages

Это инструкция процесса. Публикация доработки подтверждается успешным развёртыванием и проверкой актуального сайта, а не наличием прежнего рабочего адреса.

## Что публикует Pages

Для репозитория используется **Deploy from a branch → main → /(root)**; проверьте настройку перед обновлением. В корне должны быть `index.html`, `runtime.json` с `{"backend":"static"}` и `.nojekyll`.

Pages раздаёт HTML, CSS, JavaScript и JSON. Здесь не запускаются Python, `/api/` или Tkinter. `bootstrap.js` выбирает статические данные и клиентские правила; пути сохраняют `/sobrano/`. Наличие `server.py` в репозитории не создаёт работающий бэкенд на Pages.

Python, тесты и документация остаются исходниками для локального запуска. Не публикуйте ключи, личные файлы, кэш и виртуальные окружения.

## Локальная демонстрация

Откройте в VS Code папку с `server.py`, затем Terminal → New Terminal:

```powershell
py server.py
```

Адрес: http://127.0.0.1:8080/. Если порт занят, `py server.py --port 8081` и http://127.0.0.1:8081/. При отсутствии `py` используйте `python`. Можно запустить START.bat. Во втором терминале `py desktop_app.py` или START-DESKTOP.bat открывает оконную программу на общих Python-модулях.

Проверка API:

```powershell
Invoke-RestMethod "http://127.0.0.1:8080/api/health"
$r = Invoke-RestMethod -Uri "http://127.0.0.1:8080/api/configuration" -Method Post -ContentType "application/json" -Body '{"parts":{"gpu":85}}'
$r.assessments.p40 | ConvertTo-Json -Depth 5
```

p85 — RTX 4090, p40 — DeepCool PK550D 550 Вт. Ожидаемый `allowed: false` — результат Python. Успех и ошибочный запрос для выступления описаны в [DEFENSE.md](../DEFENSE.md).

Статический режим: `py -B -m http.server 8000 --bind 127.0.0.1` → http://127.0.0.1:8000/.

## Проверка до отправки

```powershell
py -B -m unittest discover -s tests
node tools/test-javascript.cjs
node tests/browser-smoke.cjs
git diff --check
git status --short --branch
```

Браузерному тесту нужны Node.js 22+ и Chrome. Он использует временные серверы и проверяет оба режима. Записывайте фактический результат, версию и условия запуска. Прежние числа из `FINAL_REPORT.md`/`QA.md` не подтверждают новый код автоматически.

Ручной сценарий: выбор → HTTP → расчёт → результат; неверные значения; отказ API; мобильный каталог; сохранение/загрузка состава в Python-программе. Ручной тест отмечается выполненным только после фактического показа.

## Отправка и обновление main

Сначала сохраните изменения в отдельной рабочей ветке, просмотрите diff, получите актуальную историю `git fetch origin`. Не включайте личные сохранённые файлы или секреты. Соблюдайте согласованный с владельцем порядок публикации.

Создайте pull request проверенной ветки в `main`, просмотрите результат и объедините после проверки. Используйте обычный push без `--force`. Если удалённая ветка изменилась, получите её изменения, разберите конфликты и повторите затронутые проверки.

Обновление `main` запускает Pages. Отправка отдельной ветки сама по себе не обновляет действующий сайт.

## Подтверждение публикации

1. В Actions найдите `pages build and deployment` для отправленного коммита main.
2. Дождитесь Success сборки и развёртывания.
3. Откройте сайт, `/runtime.json`, `data/catalog.json`, `data/offers.json`. Режим должен быть `static`.
4. Проверьте актуальные ресурсы и основные действия; при необходимости обновите Ctrl+F5.
5. Отдельно отметьте ограничения фотографий: работоспособность интерфейса не доказывает доступность всех внешних источников.

Прогон по опубликованному адресу:

```powershell
$env:SOBRANO_PUBLIC_URL="https://china1602-glitch.github.io/sobrano/"
node tests/browser-smoke.cjs
Remove-Item Env:SOBRANO_PUBLIC_URL
```

Локальные серверы в этом режиме не запускаются. На Pages не должно быть обращений к localhost или обязательному Python API. Один HTTP 200 от главной не доказывает правильность всего сценария.

## Телефон и хранение

Публичную ссылку Pages можно передать другим людям. Для временного показа Python в одной доверенной Wi-Fi-сети запустите `py server.py --host 0.0.0.0`, узнайте IPv4 компьютера командой `ipconfig` и откройте `http://IPv4:8080/` на телефоне. Используйте адрес компьютера, а не `0.0.0.0` или `127.0.0.1`. Брандмауэр и изоляция сети могут мешать; фактическую связь надо проверить на устройствах. Обычный запуск по умолчанию локальный.

localStorage раздельный для разных адресов/браузеров. Ссылка переносит состав, но не включает Python на Pages. При работе на localhost интерфейс поясняет ограничение ссылки и предлагает отдельный перенос состава в опубликованную статическую версию.

## Ограничения

Цены не обновляются автоматически, снимки и расчётные значения различаются. Изображения линейки подписаны; внешним фото нужен Интернет. Совместимость ограничена известными характеристиками. Аккаунтов, оплаты, заказов и серверной базы личных сборок нет.
