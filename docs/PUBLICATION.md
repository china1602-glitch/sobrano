## Источник GitHub Pages

Проверенная настройка: **Source → Deploy from a branch**, **Branch → main**, **Folder → /(root)**. В API GitHub этому соответствует `build_type=legacy`, `source.branch=main`, `source.path=/`.

В корне находятся `index.html` и `runtime.json` с `{"backend":"static"}`. Файл `.nojekyll` позволяет публиковать уже готовые статические файлы без обработки Jekyll.

В репозитории сохраняются Python, JSON, тесты и документация. Секретные конфигурации, виртуальные окружения, зависимости и Python-кэш исключены через `.gitignore`. Каталог и предложения магазинов остаются исходными. `../local/` не входит в этот Git-репозиторий.

## Почему Python не запускается на Pages

GitHub Pages раздаёт HTML, CSS, JavaScript и другие готовые файлы. В этой публикации нет постоянно работающего процесса Python и маршрутов `/api/`. Сохранённый в репозитории `server.py` остаётся исходником для локального запуска.

На Pages `js/bootstrap.js` читает статический runtime, загружает JSON и запускает клиентские правила поиска, цен и совместимости. Пути относительно корня сайта вычисляются из адреса bootstrap, поэтому подпапка `/sobrano/` сохраняется.

Локально `server.py` сам отвечает на `/runtime.json` режимом python. Файл на диске не меняется. Браузер отправляет настоящие запросы в Python API. Проверка двух режимов нужна перед каждой публикацией.

## Быстрый запуск на защите

```powershell
code "$HOME\sobrano-work\github"
cd "$HOME\sobrano-work\github"
python server.py
```

Локальный сайт: http://127.0.0.1:8080/. При занятом порте — `python server.py --port 8081`, адрес http://127.0.0.1:8081/.

Во втором терминале:

```powershell
Invoke-RestMethod "http://127.0.0.1:8080/api/health"
$r = Invoke-RestMethod -Uri "http://127.0.0.1:8080/api/configuration" -Method Post -ContentType "application/json" -Body '{"parts":{"gpu":85}}'
$r.assessments.p40 | ConvertTo-Json -Depth 5
```

Для p40 (БП DeepCool PK550D 550 Вт) с выбранной RTX 4090 результат `allowed` должен быть `false`. Индексы относятся к сохранённому каталогу.

## Проверки перед отправкой

```powershell
python -B -m unittest discover -s tests
node --test tests/*.test.cjs
node tests/browser-smoke.cjs
git diff --check
git status --short --branch
```

Браузерный тест использует установленный Chrome. В локальном прогоне проверяются Python и статический режим, все 190 моделей и 22 сборки. В тестах ожидаемые HTTP-ошибки специально проверяют отклонение неверного ввода и отказ API.

После публикации проверяйте настоящий адрес тем же браузерным тестом:

```powershell
$env:SOBRANO_PUBLIC_URL="https://china1602-glitch.github.io/sobrano/"
node tests/browser-smoke.cjs
Remove-Item Env:SOBRANO_PUBLIC_URL
```

В этом режиме локальные серверы не запускаются: Chrome работает с Pages. Проверяются девять страниц, переходы, поиск, фильтры, избранное, сравнение, конфигуратор, TXT, ссылки, мобильная вёрстка и две темы; подробно открывается по модели каждой из восьми категорий и все 22 сборки. В Network не должно быть обращений к API или localhost.

## Безопасное обновление main

Сначала сохраните изменения коммитом в рабочей ветке, затем выполните `git fetch origin`. Проверьте различия с `origin/main`.

Если локальная main не содержит своих дополнительных коммитов, её можно обновить командой `git merge --ff-only origin/main`. После перехода на main объедините проверенную ветку обычным merge. При конфликтах остановитесь и разберите их до отправки.

`git push origin main` выполняется без force. Если удалённая ветка успела измениться, обычный push будет отклонён: получите новые изменения и повторно проверьте объединение. Не заменяйте это force push.

## Как подтвердить развёртывание

1. Откройте Actions и найдите `pages build and deployment` для отправленного коммита main.
2. Дождитесь статуса **Success**, включая шаги build/deploy.
3. Откройте сайт и `/runtime.json`: режим должен быть static.
4. Проверьте загрузку `data/catalog.json` и `data/offers.json`.
5. Запустите проверку с SOBRANO_PUBLIC_URL. Убедитесь, что актуальные файлы опубликованы, а не только доступны старые страницы из кэша.

Один ответ HTTP 200 от прежнего сайта не подтверждает публикацию нового коммита. Нужны успешное развёртывание, актуальные ресурсы и работа интерфейса.

## Ограничения демонстрации

Фото загружаются с внешних сайтов и требуют Интернета. Часть фото — подписанные изображения линейки, у одной модели фото отсутствует. Цены не обновляются автоматически; снимки и учебные оценки различаются. Проверка комплектующих ограничена известными характеристиками. Локальное хранилище Pages и localhost раздельное, поэтому избранное и состав на этих адресах могут различаться.
