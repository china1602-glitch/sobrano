# СОБРАНО: запуск в VS Code и демонстрация

Инструкция относится к версии с `server.py`. Python запускает локальный HTTP-сервер, отдаёт страницы и отвечает на `/api/health`. Каталог, фильтры, проверка совместимости и бюджет выполняются JavaScript в браузере. Это точное разделение текущих частей проекта.

## 1. Скачать и открыть проект

1. Откройте на GitHub подготовленную версию, в которой есть `server.py`, и нажмите **Code → Download ZIP**.
2. Сохраните старые правки через **File → Save All / Файл → Сохранить всё**. Щёлкните в терминале старого сервера и нажмите **Ctrl+C**.
3. Сохраните старую папку целиком, например переименуйте `sobrano` в `sobrano-backup`.
4. Распакуйте ZIP в отдельную чистую папку. Внутри архива обычно есть ещё одна папка с названием репозитория и ветки: войдите в неё.
5. В VS Code выберите **File → Open Folder / Файл → Открыть папку**. Откройте именно папку, где непосредственно лежат **`index.html` и `server.py`**, а рядом находятся `css`, `js`, `assets`, `docs`, `tests` и `.vscode`.
6. Выполните **File → Save All**. Сохраняйте структуру подпапок: `app.js` остаётся в `js`, а `style.css` — в `css`.

Все девять HTML-страниц нужны. `builds.html` показывает список сборок, `build.html` — одну сборку, `product.html` — одну модель.

## 2. Запустить Python в нижнем терминале

Исходники редактируются в центральном редакторе. Следующие команды вводятся **в нижнем терминале**, открытом через **Terminal → New Terminal / Терминал → Создать терминал**:

```powershell
py --version
py server.py --port 8080
```

Первая команда показывает установленную версию Python 3, вторая запускает сервер. Откройте **http://127.0.0.1:8080/**. Терминал остаётся открытым, пока работает локальный сайт. Остановка — **Ctrl+C** в терминале. После правок сохраните файлы и обновите браузер через **Ctrl+F5**.

Если терминал оказался в другой папке, сначала выполните `cd` с вашим фактическим путём. Для исходной папки проекта пример такой:

```powershell
cd "C:\Users\Студент\Desktop\sobrano"
py server.py --port 8080
```

- Если `py` не найден, проверьте `python --version` и используйте `python server.py --port 8080`. Если обе команды отсутствуют, установите Python 3 с [python.org](https://www.python.org/downloads/) и заново откройте VS Code.
- Если `server.py` не найден, проверьте выбранную папку. Если порт занят, остановите прежний процесс через Ctrl+C либо выполните `py server.py --port 8081` и откройте **http://127.0.0.1:8081/**.
- При `ERR_CONNECTION_REFUSED` проверьте, запущен ли сервер и совпадает ли порт в адресе с командой запуска.

Сервер использует стандартную библиотеку Python. Пакеты через `pip` для его запуска не нужны; Node.js требуется отдельно для JavaScript-тестов.

## 3. Показать реальную работу Python

Откройте **http://127.0.0.1:8080/api/health**. Запущенный `server.py` формирует JSON с полями:

| Поле                           | Значение                                                       |
| ------------------------------ | -------------------------------------------------------------- |
| `status`, `project`, `backend` | Состояние `ok`, название `СОБРАНО` и язык обработчика `Python` |
| `pythonVersion`                | Версия именно запущенного Python-процесса                      |
| `serverTime`                   | Время формирования ответа сервером с часовым смещением         |
| `frontend`                     | Клиентские языки: HTML, CSS, JavaScript                        |
| `purpose`                      | Назначение процесса: локальный HTTP-сервер и диагностика       |

Обновление через некоторое время даёт новое `serverTime`; ответ имеет `Cache-Control: no-store`. В нижнем терминале появляются реальные HTTP-запросы. Например, **схема строки журнала**, а не доказательство запуска на вашем компьютере:

```text
127.0.0.1 - - [время запроса] "GET /api/health HTTP/1.1" 200 -
```

`200` — успешный ответ, `304` для статического файла — использование кэша. Точный набор запросов зависит от действий и кэша браузера. На защите показывайте живой терминал после собственных действий.

## 4. F5 и точка останова

Для `.vscode/launch.json` нужны бесплатные расширения Microsoft **Python** (`ms-python.python`) и **Python Debugger** (`ms-python.debugpy`).

1. Нажмите **Ctrl+Shift+X**, найдите и установите расширения; проверьте издателя **Microsoft**.
2. Выполните **Ctrl+Shift+P → Python: Select Interpreter** и выберите установленный Python 3.
3. Остановите прежний сервер на порту 8080 через Ctrl+C.
4. В `server.py` найдите класс `SobranoHandler`, метод `do_GET` и строку `if urlsplit(self.path).path == "/api/health":`. Щёлкните слева от номера этой строки: появится красная точка останова. Также работает **F9**.
5. Откройте **Run and Debug / Запуск и отладка** через **Ctrl+Shift+D**, выберите **«СОБРАНО: запустить Python-сервер»** и нажмите **F5**.
6. В браузере откройте `/api/health`. Когда VS Code остановится, посмотрите `self.path` и `self.command` в переменных или Debug Console: для этого запроса это `/api/health` и `GET`.
7. Нажмите **F5**, чтобы продолжить выполнение и получить JSON. Завершение отладочного запуска — **Shift+F5**.

Пока обработчик остановлен отладчиком, браузер может ждать ответ. Продолжение выполнения завершает обработку запроса.

## 5. Что находится в файлах

| Файл                                  | Что объяснить                                                                                                   |
| ------------------------------------- | --------------------------------------------------------------------------------------------------------------- |
| `server.py`                           | `main`, `create_server`, `SobranoHandler.do_GET`, `send_health`: запуск, HTTP и диагностический JSON            |
| `.vscode/launch.json`                 | Запуск Python-файла с портом 8080 в терминале VS Code                                                           |
| HTML-страницы, `css/style.css`        | Оболочка разделов, порядок скриптов, оформление, две темы и адаптация к телефону                                |
| `js/data.js`                          | Модели, характеристики, учебные цены и 22 готовые конфигурации                                                  |
| `js/core.js`                          | `spec`, `brief`, `buildParts`, `parseParts`, `partsString`, `check`: характеристики, состав и итоговая проверка |
| `js/compatibility.js`                 | `assess`, `filter`: отбор кандидата относительно уже выбранных деталей                                          |
| `js/catalog-ui.js`                    | `facets`, `filter`, `filterPanel`: поиск, параметры категории и сортировка                                      |
| `js/offers.js`, `js/pricing.js`       | Снимки магазинов; `offersFor`, `price`, `budget`: выбор цены и общий бюджет                                     |
| `js/media.js`, `js/product-images.js` | Фотографии моделей/линеек, источники, подписи и недоступные изображения                                         |
| `js/app.js`                           | `catalogue`, `builder`, `productDetail`, события, сохранение, ссылки и TXT                                      |
| `tests/`, `docs/`                     | Проверки, источники данных, ограничения и документация                                                          |

Браузер запрашивает HTML/CSS/JavaScript у Python-сервера и выполняет интерфейс. Избранное, сравнение и состав хранятся в `localStorage` браузера по ключу `sobrano:diploma:1`. Это **браузерное хранилище**, а не серверная база данных. В нынешней версии сервер не сохраняет сборки в SQLite/PostgreSQL. Если диплом требует выполнение бизнес-логики именно на Python, следующим этапом потребуется серверное API каталога и расчётов.

## 6. Пятиминутная демонстрация

Время — план выступления, а не измерение быстродействия программы.

| Время     | Действие и объяснение                                                                                                                                   |
| --------- | ------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 0:00–0:40 | Показать папку и `server.py`, выполнить `py server.py --port 8080`. Объяснить запуск из исходников Python.                                              |
| 0:40–1:20 | Открыть сайт и `/api/health`; показать свежий запрос в терминале. Объяснить HTTP и клиентскую часть.                                                    |
| 1:20–2:10 | В каталоге выбрать RAM, отфильтровать DDR5/объём и открыть модель. Показать характеристики и постоянную ссылку.                                         |
| 2:10–3:10 | Очистить демонстрационный состав, **сначала выбрать NVIDIA GeForce RTX 4090**. Показать, что даже без CPU БП ниже известной рекомендации GPU исключены. |
| 3:10–3:50 | Выбрать БП и CPU, показать обновлённый итог. Объяснить запас мощности и пределы проверки неизвестных размеров/питания.                                  |
| 3:50–4:30 | Открыть готовую сборку, состав, ссылку конфигурации и TXT-экспорт. Объяснить сумму и перенос состава.                                                   |
| 4:30–5:00 | Сравнить предложение с магазином/датой и расчётную цену другой модели. Объяснить источники и ручное обновление.                                         |

Один пункт можно заменить показом Python-отладчика из раздела 4. Заранее отрепетируйте на своём компьютере. Нужный личный состав перед очисткой сохраните ссылкой или TXT.

`compatibility.assess()` подставляет кандидата вместо старой детали его категории и проверяет связанные параметры. Для БП учитываются рекомендация GPU и расчёт нагрузки с запасом. Поэтому GPU-first работает без обязательного первого CPU. Неизвестные сведения не считаются нулями; ограничения перечисляет общий результат. Подробности — [COMPATIBILITY.md](COMPATIBILITY.md).

## 8. Десять вопросов для подготовки

**1. Для чего нужен СОБРАНО?**
Это информационный каталог для Казахстана: сравнение моделей, готовые конфигурации, свой состав и бюджет в тенге. Оплата и оформление заказа отсутствуют.

**2. Что написано на Python?**
`server.py` запускает HTTP-сервер, отдаёт файлы и обрабатывает `/api/health`. Каталог и расчёты выполняются JavaScript. Это можно показать в исходниках и через точку останова Python.

**3. Как разделены frontend и backend?**
Сервер получает HTTP-запрос и отправляет ответ; браузер строит страницу по HTML/CSS и выполняет JavaScript. Нынешний локальный сервер использует стандартную библиотеку, без Flask/Django. Расширенная серверная бизнес-логика требует отдельных Python-обработчиков.

**4. Где данные и текущая сборка?**
Каталог — в `js/data.js`, предложения — в `js/offers.js`, выбор — в `localStorage`. Это данные конкретного браузера и адреса: другой порт/домен может иметь другое хранилище. Ссылка передаёт состав в параметре `parts`. Серверной базы данных в этой версии нет.

**5. Откуда цены?**
Это обозначенные снимки магазинов с датой и учебные оценки. Снимки обновляются вручную. Для бюджета берётся минимальный пригодный снимок не старше 30 дней, иначе оценка. Магазин подтверждает действующие цену и наличие. Доставка, ОС, периферия и сборщик не включены. Источники — [PRICE-SOURCES.md](PRICE-SOURCES.md).

**6. Как проверяется совместимость?**
Сокет CPU сравнивается с платой, RAM — с CPU/платой, размеры — с корпусом, БП — с рекомендацией GPU и расчётным порогом. Порядок выбора произвольный. BIOS, QVL, кабели, охлаждение и реальные зазоры проверяются отдельно; неизвестные параметры остаются ограничением проверки.

**7. Что доказывает `/api/health`?**
Работающий Python-процесс обработал запрос и сформировал JSON с версией и временем. Этот маршрут не означает перенос всех фильтров и расчётов на сервер: их расположение видно в исходниках.

**8. Как связаны GitHub Pages и локальный Python?**
GitHub Pages размещает статические HTML/CSS/JavaScript-файлы и не выполняет Python. `/api/health` предназначен для локального запуска. Этот сервер слушает только `127.0.0.1` на вашем компьютере; публичный браузерный интерфейс открывается по ссылке GitHub Pages.

**9. Как проверялась работа?**
Есть Python-тесты сервера и JavaScript-тесты расчётов, правил, фильтров, цен и изображений; команды приведены выше. Браузерные сценарии и ограничения записаны в [QA.md](QA.md). На защите покажите собственный живой запрос и воспроизводимый подбор. Внешние фото и действующие магазинные цены проверяются отдельно.

**10. Как объяснить процесс разработки и инструменты помощи?**
Назовите фактически использованные инструменты, источники и готовые фрагменты, затем собственные изменения и проверенные части. Подготовьте понятный пример: фильтр, обработчик выбора или дополнительный тест. Объяснение кода и самостоятельное воспроизведение показывают понимание; источники фотографий и цен остаются в документации.
