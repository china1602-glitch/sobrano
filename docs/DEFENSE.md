# СОБРАНО: запуск в VS Code и подготовка к защите

В локальной версии Python выполняет фильтрацию товаров, подбор кандидатов, проверку совместимости и расчёт бюджета. Браузер отправляет запросы к API и показывает ответы. На GitHub Pages работает статический режим с клиентскими правилами: этот хостинг не выполняет Python.

## 1. Скачать и открыть проект

1. На GitHub откройте подготовленную версию и выберите **Code → Download ZIP**.
2. В VS Code сохраните старые правки через **File → Save All / Файл → Сохранить всё**. В терминале прежнего сервера нажмите **Ctrl+C**.
3. Сохраните старую папку целиком, например переименуйте `sobrano` в `sobrano-backup`.
4. Распакуйте ZIP в отдельную чистую папку. Внутри архива обычно есть ещё одна папка с названием репозитория и ветки: войдите в неё.
5. Выберите **File → Open Folder / Файл → Открыть папку**. Откройте папку, где непосредственно лежат **`index.html` и `server.py`**, а рядом находятся `backend`, `data`, `css`, `js`, `assets`, `docs`, `tests` и `.vscode`.
6. Переносите подпапки целиком. `app.js` должен остаться внутри `js`, `style.css` — внутри `css`, а Python-модули — внутри `backend`.

Все девять HTML-страниц нужны. `builds.html` показывает список сборок, `build.html` — одну сборку, `product.html` — одну модель. Python-код не нужно вставлять в HTML или CSS.

## 2. Запустить Python в нижнем терминале

Код редактируют в центральном редакторе. Следующие команды вводите **в нижнем терминале**, открытом через **Terminal → New Terminal / Терминал → Создать терминал**:

```powershell
py --version
py server.py --port 8080
```

Первая команда показывает версию Python, вторая запускает сервер. Откройте **http://127.0.0.1:8080/**. Оставьте терминал открытым; остановка — **Ctrl+C**. HTML/CSS/JavaScript после сохранения обновляйте через **Ctrl+F5**. После изменения Python-модулей перезапустите сервер. JSON-данные сервер читает при запросах; после их изменения обновите страницу.

Если терминал открыт в другой папке, сначала перейдите по своему фактическому пути. Для исходной папки пример такой:

```powershell
cd "C:\Users\Студент\Desktop\sobrano"
py server.py --port 8080
```

- Если `py` не найден, проверьте `python --version` и используйте `python server.py --port 8080`. Если обе команды отсутствуют, установите Python 3 с [python.org](https://www.python.org/downloads/) и заново откройте VS Code.
- Если не найден `server.py`, проверьте выбранную папку. Если занят порт, остановите прежний процесс через Ctrl+C либо запустите `py server.py --port 8081` и откройте **http://127.0.0.1:8081/**.
- При `ERR_CONNECTION_REFUSED` проверьте, работает ли сервер и совпадает ли порт в адресе с командой запуска.
- Не используйте `py -m http.server` для демонстрации backend: эта стандартная команда не подключает обработчики проекта.

Сервер использует стандартную библиотеку Python. Установка Flask, Django или пакетов через `pip` для него не нужна. Node.js нужен отдельно только для JavaScript-тестов.

## 3. Убедиться, что сайт обращается к Python

Откройте **http://127.0.0.1:8080/api/health**: работающий процесс возвращает JSON с диагностикой. Затем откройте **http://127.0.0.1:8080/api/catalog**. Это ответ с данными каталога и серверными результатами, который используется при загрузке локального интерфейса.

Для проверки реальных действий интерфейса:

1. Вернитесь на сайт и откройте инструменты разработчика браузера через **F12**.
2. Выберите вкладку **Network / Сеть**, затем фильтр **Fetch/XHR**. При необходимости обновите страницу.
3. В каталоге измените поиск, категорию или сортировку. Откройте запрос **`api/products`**: в **Payload / Query String Parameters** видны отправленные параметры, в **Response / Ответ** — упорядоченные идентификаторы отобранных Python товаров.
4. В конфигураторе выберите или замените компонент. Откройте **`api/configuration`**, проверьте метод **POST**, переданный состав и ответ с проверкой и расчётом.
5. Посмотрите нижний терминал VS Code: в нём появляются те же реальные обращения.

Структура журнала, **не доказательство запуска на вашем компьютере**:

```text
127.0.0.1 - - [время запроса] "GET /api/products?... HTTP/1.1" 200 -
127.0.0.1 - - [время запроса] "POST /api/configuration HTTP/1.1" 200 -
```

`200` — успешный ответ. `304` для статического файла означает использование кэша. Точный набор запросов зависит от ваших действий. `/api/health` подтверждает работу процесса, а запросы товаров и конфигурации вместе с отладчиком показывают выполнение бизнес-логики.

Для текущего набора пример тела запроса после выбора только RTX 4090 — `{"parts":{"gpu":85}}`. В ответе `assessments.p40.allowed` будет `false`: `p40` — DeepCool PK550D. При этом полный состав ещё не собран, поэтому `check.need` не становится окончательным расчётом мощности без CPU. Это показывает различие проверки кандидата и проверки всего состава.

По адресу `/runtime.json` локальный сервер сообщает режим Python. На GitHub Pages этот файл сообщает статический режим. Если Python API отвечает ошибкой, локальная страница показывает ошибку и повтор запроса; она не должна незаметно считать результат клиентскими правилами.

## 4. F5 и точка останова в правиле совместимости

Для конфигурации `.vscode/launch.json` нужны бесплатные расширения Microsoft **Python** (`ms-python.python`) и **Python Debugger** (`ms-python.debugpy`).

1. Через **Ctrl+Shift+X** установите оба расширения; проверьте издателя **Microsoft**.
2. Выполните **Ctrl+Shift+P → Python: Select Interpreter** и выберите установленный Python 3.
3. Остановите прежний сервер на порту 8080 через **Ctrl+C**.
4. Откройте **`backend/compatibility.py`**, найдите функцию **`assess`**. Поставьте точку останова на строке **`if psu and (cpu or gpu) and candidate["c"] in ...`**: щёлкните слева от номера строки или нажмите **F9**. Для остановки только на проверке PK550D с выбранной RTX 4090 нажмите правой кнопкой на точку → **Edit Breakpoint / Изменить точку останова → Expression** и задайте условие `candidate["id"] == "p40" and selected.get("gpu") == 85`.
5. Откройте **Run and Debug / Запуск и отладка** через **Ctrl+Shift+D**, выберите **«СОБРАНО: запустить Python-сервер»** и нажмите **F5**.
6. В браузере откройте конфигуратор, сохраните нужный личный состав ссылкой или TXT, затем очистите демонстрационный состав. **Сначала выберите NVIDIA GeForce RTX 4090**.
7. Когда VS Code остановится, посмотрите переменные `candidate`, `selected`, `gpu` и `psu`. Python оценивает очередного кандидата относительно выбранного GPU. Остановка может происходить несколько раз: проверяются разные варианты.
8. Для подробного разбора поставьте вторую точку на условии **`if psu_known and lower_bound > 0 ...`** в той же функции. Здесь сравниваются мощность блока и уже известный нижний порог. Пошаговое выполнение — **F10**, продолжение — **F5**.
9. Снимите точки останова и нажмите **F5**, чтобы браузер получил ответ. Блок 550 Вт не должен предлагаться для RTX 4090. Завершение отладки — **Shift+F5**.

Настройка F5 задаёт `SOBRANO_DEBUG=1`: браузер ожидает ответ без тайм-аута, пока обработчик остановлен отладчиком. При выборе другого состава конкретные значения переменных будут другими. Заранее отрепетируйте сценарий на своём компьютере.

## 5. Что объяснить по исходникам

| Файл                                                                     | Роль                                                                                                           |
| ------------------------------------------------------------------------ | -------------------------------------------------------------------------------------------------------------- |
| `server.py`                                                              | Запуск HTTP-сервера, разбор маршрута, чтение запроса и отправка JSON                                           |
| `backend/catalog.py`                                                     | `normalize_products`, `filter_products`, `facets`, `build_parts`: подготовка моделей, поиск, фильтры и составы |
| `backend/compatibility.py`                                               | `assess` проверяет кандидата, `check` — состав целиком, `validate_parts` — входные индексы                     |
| `backend/pricing.py`                                                     | `prices_for` выбирает пригодную цену, `budget` суммирует выбранные компоненты                                  |
| `data/catalog.json`                                                      | Исходные строки 190 моделей, 22 готовые конфигурации и метаданные изображений                                  |
| `data/offers.json`                                                       | Зафиксированные предложения магазинов: цена, дата, ссылка, наличие и точная модель                             |
| `js/bootstrap.js`, `runtime.json`                                        | Выбор Python-режима или статического режима и загрузка данных                                                  |
| `js/backend-client.js`                                                   | Запросы локального интерфейса к Python API                                                                     |
| `js/app.js`                                                              | Отрисовка, обработчики действий, адресные ссылки, TXT и сохранение выбора                                      |
| `js/core.js`, `js/compatibility.js`, `js/catalog-ui.js`, `js/pricing.js` | Клиентские правила статического режима и подготовка представления                                              |
| HTML-страницы, `css/style.css`                                           | Разделы, доступные элементы, две темы и адаптивная вёрстка                                                     |
| `js/media.js`, `js/product-images.js`                                    | Фото, различие модели и линейки, источники, подписи и заглушки                                                 |
| `tests/`, `docs/`                                                        | Воспроизводимые проверки, ограничения и источники                                                              |

`data/catalog.json` и `data/offers.json` — файловые источники данных, а не SQLite/PostgreSQL. Избранное, сравнение и текущий состав хранятся в `localStorage` браузера с ключом `sobrano:diploma:1`. Другой браузер, домен или порт может иметь другое хранилище. Ссылка передаёт состав в параметре `parts`; сервер проверяет полученные индексы, а не доверяет готовому заключению браузера.

## 6. Пятиминутная демонстрация

Время — план выступления, а не измеренная скорость программы.

| Время     | Действие                                                                                                                                                                   |
| --------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 0:00–0:40 | Показать `server.py`, папку `backend` и запуск `py server.py --port 8080`. Объяснить Python backend и браузерный интерфейс.                                                |
| 0:40–1:20 | Открыть каталог, изменить поиск и показать `GET /api/products` в Network и терминале.                                                                                      |
| 1:20–2:10 | Выбрать RAM, отфильтровать DDR5 и объём; открыть модель с характеристиками и постоянной ссылкой.                                                                           |
| 2:10–3:10 | В очищенном конфигураторе сначала выбрать RTX 4090. Показать `POST /api/configuration` и отсутствие 550-ваттных БП. При подготовленном отладчике кратко показать `assess`. |
| 3:10–3:50 | Выбрать остальные детали, показать сумму и перечисленные ограничения проверки.                                                                                             |
| 3:50–4:30 | Открыть готовую сборку, состав, ссылку и TXT. Объяснить, что цена складывается из компонентов.                                                                             |
| 4:30–5:00 | Показать снимок цены с магазином/датой и учебную оценку другой модели. Назвать различие и способ обновления.                                                               |

Для правила мощности берётся большее из рекомендации GPU и расчётной нагрузки с запасом. Неизвестные данные не считаются нулями. Полная аппаратная совместимость не гарантируется: BIOS, QVL, разъёмы и геометрию проверяют отдельно. Подробности — [COMPATIBILITY.md](COMPATIBILITY.md).

## 8. Десять вопросов для подготовки

**1. Для чего нужен СОБРАНО?**
Это информационный сервис для Казахстана: поиск и сравнение комплектующих, готовые конфигурации, свой состав и бюджет в тенге. Оформление заказа и оплата отсутствуют.

**2. Что написано на Python?**
HTTP-обработчики в `server.py`, фильтры в `backend/catalog.py`, выбор цен и бюджет в `backend/pricing.py`, проверка совместимости и кандидатов в `backend/compatibility.py`. В локальной версии интерфейс действительно вызывает эти модули через API. Это видно в Network и на точке останова.

**3. Зачем тогда JavaScript?**
Он обрабатывает действия пользователя, отправляет запросы и строит интерфейс по ответу. Для GitHub Pages есть статический режим с клиентскими правилами, поскольку этот хостинг Python не выполняет. В режиме Python ошибка API показывается, а не скрывается под клиентским расчётом.

**4. Где данные и сохранённый выбор?**
Каталог и составы — в `data/catalog.json`, предложения — в `data/offers.json`. Избранное, сравнение и текущая сборка — в `localStorage` конкретного браузера. Серверной SQL-базы в этой версии нет. Ссылка `parts` передаёт состав, но не чужое браузерное хранилище.

**5. Откуда цены?**
Это обозначенные снимки магазинов с датами и учебные оценки. Для бюджета берётся минимальный пригодный снимок не старше 30 дней, иначе оценка. Новые цены сами не загружаются; записи обновляют после сверки страницы магазина. Доставка, ОС, периферия и сборщик не включены. Источники — [PRICE-SOURCES.md](PRICE-SOURCES.md).

**6. Все ли детали совместимы?**
Нет. В каталоге есть AM4, AM5 и LGA1700, DDR4 и DDR5, разные размеры и требования питания. Проверка отбирает подходящих кандидатов по известным параметрам. Неизвестные значения дают ограничение, а не положительное подтверждение. BIOS, QVL, кабели и реальные зазоры требуют отдельной сверки.

**7. Как доказать, что расчёт выполнен backend?**
Показать запрос `POST /api/configuration`, переданный состав и ответ; поставить точку останова в `backend/compatibility.py` и воспроизвести выбор GPU → БП. `/api/health` показывает состояние процесса, но один диагностический ответ не демонстрирует бизнес-логику.

**8. Как работает сайт по публичной ссылке?**
GitHub Pages отдаёт HTML/CSS/JavaScript и JSON; расчёты выполняются статическими клиентскими модулями. Локальная версия через `server.py` использует Python API и слушает `127.0.0.1` на вашем компьютере. Публичный адрес Pages не является адресом локального Python-процесса.

**9. Как проверялась работа?**
Есть Python-тесты движка и HTTP API, JavaScript-тесты статического режима и браузерные сценарии. Команды приведены выше, условия и ограничения — в [QA.md](QA.md). На защите стоит показать свой запуск тестов и живой запрос. Текущее наличие в магазинах и загрузка внешних фотографий проверяются отдельно.

**10. Как объяснить процесс разработки и помощь инструментов?**
Назовите фактически использованные инструменты, источники и готовые фрагменты, затем собственные изменения и выполненные проверки. Подготовьте понятный пример правила, обработчика или теста и воспроизведите его самостоятельно. Источники цен и фотографий сохранены в документации.
