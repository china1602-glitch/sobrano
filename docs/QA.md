# Проверка версии от 20 октября 2026

Ниже разделены проверки Python backend и предыдущих этапов интерфейса. Браузерные сценарии выполнялись в Chromium на локальном сервере, включая статическое размещение в подпапке `/sobrano/`. Прямой адрес GitHub Pages и внешние бинарные фотографии недоступны из сети среды проверки.

## Python backend и общий источник данных

Локальная версия выполняет поиск, фильтрацию, подбор кандидатов, проверку состава и бюджет в Python-модулях `backend/`. `server.py` подключает их к API. Статический режим GitHub Pages использует те же `data/catalog.json` и `data/offers.json` с клиентскими правилами. Старые файлы `js/data.js` и `js/offers.js` удалены после перевода загрузчика и тестов; 190 исходных строк моделей, 22 состава, 8 предложений и метаданные перенесены без потерь.

Проверен 21 интеграционный сценарий HTTP API: живой `/api/health`, режим `/runtime.json`, выдача каталога и серверных расчётов, поиск и характеристики, цена и сортировка, отбор совместимости, избранный поднабор, проверка состава и кандидатов, подбор готовых сборок по бюджету, валидация индексов и JSON, ограничение размера запроса, ошибки маршрутов и методов. Отдельно проверено, что изменение JSON-данных читается при следующем запросе без перезапуска процесса.

55 проверок Node.js проходят: 47 проверок прежних модулей и 8 проверок загрузчика после миграции на JSON. Загрузчик проверяется для подпапки GitHub Pages, обоих режимов и отказа Python API: ошибка Python-режима показывается пользователю, без скрытого расчёта через статические правила.

Всего проходят **59 Python-тестов**: 21 тест HTTP API, 17 проверок правил совместимости и 21 проверка каталога/цен. Дополнительно сопоставлены Python и статический JavaScript-движок: 4744 случая, 9488 результатов `assess`/`check`, расхождений нет. Совпали результаты 90 запросов каталога, цены 190 моделей и наборы характеристик восьми категорий. Это проверка соответствия двух реализаций по текущим данным и сценариям, а не подтверждение характеристик оборудования.

## Браузерная проверка двух режимов

Пройдены **33 группы сценариев** в Headless Chromium: 27 основных (16 Python и 11 статических), три проверки доступности и источника расчётов, две проверки асинхронности и отдельная проверка очистки состава. В основном журнале сохранены 443 обращения за данными. Python-режим выполнил 183 запроса API, в том числе 77 POST проверки состава; статический режим не обращался к API. Необработанных JavaScript-ошибок и неожиданных отказов локальных HTTP-ресурсов нет. Внешние HTTPS-фотографии в этой проверке намеренно не загружались.

Проверены 18 состояний Axe WCAG: девять страниц в обоих режимах при ширине 390 px, нарушений не обнаружено. Подмена ответа API готовых сборок и их бюджета только внутри тестового браузера подтвердила использование Python-результатов. Старый задержанный ответ поиска не заменяет свежий. Исправлена обнаруженная гонка: обновление из другой вкладки во время медленного POST больше не оставляет кнопку удаления компонента заблокированной; повторные проверки гонки и очистки состава прошли. Отдельный прогон подтвердил синхронизацию вкладки во время первого API-запроса, правильный адрес после замены входящей ссылки новым составом и сохранение этого состава после перезагрузки.

- В обоих режимах открыты девять страниц; сохранены 190 моделей и 22 сборки. Проверены поиск, сортировка, характеристики, готовые сборки по задаче/бюджету и совпадение итога с суммой компонентов.
- Проверены GPU → БП и обратный порядок, RAM до CPU/платы, корпус до других деталей, неизвестные характеристики, сохранение и восстановление состава через URL, исправление старого конфликта и синхронизация вкладок.
- По сети подтверждены запросы Python API для поиска, готовых сборок и состава. В статическом режиме обращений к API нет: данные получены из JSON-файлов.
- В тесте Python-режима клиентские функции бизнес-логики намеренно заменены функциями, выбрасывающими ошибку. Каталог, бюджет, состав и подбор продолжили работать через сервер. Контрольная цена `123 456 ₸`, подставленная только в тестовый ответ API, отобразилась на странице; исходные цены не менялись.
- При намеренном HTTP 500 от `/api/configuration` интерфейс показывает ошибку и сохраняет прежние `localStorage`, URL и выбранное поле. Ошибка `/api/products` также видна. При отказе загрузки `/api/catalog` загрузчик показывает ошибку с повтором; статические JSON и клиентский расчёт вместо Python не используются. Эти HTTP 500 — заданные условия теста отказа.
- На мобильном экране проверены девять страниц в обоих режимах и обеих темах: горизонтального переполнения страницы не найдено.

Эта проверка выполнена в среде разработки с Linux, а не на Windows-компьютере пользователя. Интерфейс VS Code F5 здесь недоступен; собственные снимки и точка останова выполняются по [DEFENSE.md](DEFENSE.md). Результаты прежних проверок доступности приведены отдельно ниже; новый прогон включает указанные выше 18 состояний.

Для запуска F5 включён `SOBRANO_DEBUG=1`: локальный runtime отключает тайм-аут запросов, чтобы можно было рассматривать переменные на точке останова. Проверка браузером с задержками API 16 и 12 секунд подтвердила ожидание ответов и запуск Python-режима; это моделирование паузы, а не запись работы GUI VS Code.

## Повторить автоматические проверки

Полный запуск из корня проекта:

```powershell
py -m unittest discover -s tests -p "test_*.py" -v
node --test tests/*.test.cjs
```

На Linux вместо `py` используется `python3`. Стандартная библиотека Python достаточна для backend и его тестов; Node.js нужен для второй команды. Результаты предыдущих браузерных проверок ниже относятся к указанным этапам. Собственный запуск F5, запросы API и отладка правила в Windows выполняются по [DEFENSE.md](DEFENSE.md).

## Предыдущий этап: HTTP-сервер с диагностикой

До переноса бизнес-логики был добавлен `server.py` на стандартной библиотеке Python и выполнены четыре исходных интеграционных теста: живой JSON `/api/health`, HEAD без тела, загрузка страницы и скрипта, HTTP 404 для отсутствующего файла. Проверены занятый порт, некорректный номер порта и запуск абсолютного пути к серверу из другой рабочей папки.

Все девять страниц загружены в Chromium через новый сервер; выбор RTX 4090 исключает БП 550 Вт. Ошибок JavaScript и отсутствующих локальных ресурсов не было. Проверка выполнена в Linux с Python 3.12.14; она не выдаётся за запуск на компьютере пользователя. JSON-файлы настроек VS Code корректны. Интерактивный запуск F5 и собственные скриншоты пользователь делает в своём VS Code по [DEFENSE.md](DEFENSE.md).
