# Как устроена программа

## Три части

**Браузер:** HTML задаёт страницы, CSS — оформление, JavaScript — формы, переключение темы и HTTP-запросы. В `web/js/app.js` функция `request()` обращается к API через `fetch`. `showEntry()` создаёт форму дня, обработчик `submit` отправляет введённое.

**Python:** `server.py` принимает HTTP-запрос, проверяет формат и вызывает `Store` из `app/service.py`. Функции `validate_task`, `validate_entry`, `validate_profile` проверяют значения. `calculate_minutes` вычисляет рабочее время; числу часов, присланному браузером, программа не доверяет.

**SQLite:** `Store.connect()` открывает соединение с нужной базой и включает внешние ключи. В таблице `profile` хранится JSON настроек, `tasks` — задачи, `entries` — дневник, `meta` — номер версии данных. SQL-значения передаются параметрами `?`. Изменение проходит внутри транзакции: при ошибке вызывается rollback.

## Пример пути одной записи

1. Пользователь указывает 09:00–17:30, перерыв 60 минут и описание работы.
2. JavaScript отправляет `POST /api/entries?mode=personal` с JSON.
3. `Handler.write()` в `server.py` проверяет тип, размер и адрес запроса, затем вызывает `Store.mutate()`.
4. Python проверяет версию данных, дату, отсутствие второй записи за тот же день и рассчитывает `(17×60+30) − 9×60 − 60 = 450 минут`.
5. SQLite сохраняет запись, номер версии увеличивается.
6. Браузер снова запрашивает `GET /api/state`. Дневник показывает **7 ч 30 мин**, статистика считает эти же 450 минут.
7. После перезапуска запись остаётся в `storage/personal.sqlite3`.

## Что открыть перед объяснением

| Что объяснить | Где смотреть |
| --- | --- |
| Запуск и HTTP | `server.py`, `main`, `Handler.get`, `Handler.write` |
| Расчёт часов | `app/service.py`, `calculate_minutes` |
| Даты и время | `validate_entry` |
| Создание и редактирование | `Store.mutate` |
| Структуру таблиц | SQL в `Store.__init__` |
| Статистику и поиск | `Store.state` |
| Резервные копии | `backup`, `_restore` |
| Печатный отчёт | `app/reports.py`, `render_report` |
| Форму и запрос | `web/js/app.js`, `showEntry`, `request`, обработчик `submit` |
| Внешний вид | `web/css/style.css`, переменные `:root` и media queries |

`__init__.py` — отметка пакета Python, его небольшой размер нормален. `__pycache__` — автоматически создаваемый двоичный кэш, не учебный исходник.

## Живая демонстрация

Запустите сайт обычной командой и выполните действия самостоятельно:

1. В настройках укажите свои данные и план часов.
2. Создайте задачу, измените статус, найдите её поиском.
3. Запишите день 09:00–17:30 с перерывом 60 минут. Покажите рассчитанные 7 ч 30 мин.
4. Попробуйте повторную запись за ту же дату — сервер вернёт ошибку, текст формы останется.
5. Обновите страницу: запись сохранилась в SQLite.
6. Выберите период отчёта и откройте печатный дневник.
7. Скачайте резервную копию и объясните разницу между данными в SQLite и темой в браузере.

Для просмотра запросов: F12 в браузере → Network → фильтр `api`. Здесь видны настоящие GET и POST. В терминале сервера отображаются те же маршруты и HTTP-статусы.

Для отладки: остановите обычный сервер, поставьте точку останова у расчёта `duration = ...` в `calculate_minutes`, запустите F5. Сохранение дня остановит Python на этой строке. Посмотрите `start`, `end`, `pause`, затем F10 и F5. Настройка `PRAKTIKUM_DEBUG` убирает короткий сетевой тайм-аут на время отладки. В браузере запрос ожидает продолжения выполнения Python.

## Вопросы, в которых стоит разобраться

- Почему нельзя доверять присланному браузером числу часов? Клиент можно изменить; сервер повторяет проверку и расчёт.
- Зачем SQLite? Это настоящее постоянное хранилище без установки отдельного сервера БД.
- Что делает транзакция? Позволяет записать согласованное изменение целиком либо откатить его.
- Зачем версия? Запрос с устаревшим `If-Match` получает 409 и не перезаписывает данные другой вкладки.
- Что происходит при удалении задачи? Дневник сохраняется, внешний ключ становится NULL.
- Почему даты дней уникальны? Чтобы не учесть один рабочий день дважды; существующую запись можно редактировать.
- Где хранятся данные? В `storage/` на компьютере сервера; режимы разделены на две базы.
- Работает ли без Интернета? Да, интерфейс, шрифт и картинки локальные. Только внешним ссылкам на документацию нужен Интернет.
- Весь ли проект написан на Python? Нет: сервер и бизнес-логика — Python, интерфейс — HTML/CSS/JavaScript.
- Что можно доработать? Учёт нескольких студентов потребует пользователей, прав доступа и изменения модели данных.
