# Соответствие вопросам ПМ 6

Основание — переданный файл **«Основные вопросы для защиты по ПМ 6.docx»**. Он требует презентацию на **5–6 минут**, отдельное приложение Python и сайт с объяснением frontend/backend. Конкретный язык серверной части, магазин, оплата или администратор в файле не предписаны.

Это карта реальных частей проекта. Числа тестов и состояние последней версии смотрите в [ONLINE_CHECKS.md](ONLINE_CHECKS.md); наличие функции в коде и её фактическая проверка — разные вещи.

## Обязательные материалы слайдов

В файле задания прямо написано показать:

1. **По Python:** скриншот приложения и небольшой объяснимый фрагмент кода.
2. **По сайту:** внешний вид страниц, адаптивное отображение, цепочку «действие → запрос → обработка → результат».
3. **По результатам:** успешную операцию и обработку некорректных данных.

Подготовьте снимки после запуска своей копии. Достаточно:

- Окно Python с выбранной сборкой и итогом, рядом 10–15 строк `choose()`.
- Каталог и конфигуратор; отдельный снимок мобильного меню/каталога в DevTools.
- Network: POST `/api/configuration` с составом и ответом сервера.
- Подтверждение сохранения и запись в кабинете; ошибку неверного пароля или поля.

Снимки нужны **для презентации**, а не для исполнения сайта. Не включайте в слайды пароли, cookie, CSRF-токены или личные данные из базы.

## Короткие ответы на возможные вопросы

**Что такое frontend?** HTML задаёт структуру страницы, CSS — оформление и размеры, JavaScript — действия кнопок и изменение страницы. Эти файлы исполняются в браузере.

**Что такое backend?** Программа, работающая в серверном процессе. Здесь это JavaScript в Node.js. Она принимает HTTP-запрос, проверяет данные, выполняет расчёт или SQL и возвращает JSON.

**Где используется Python?** В отдельной оконной программе Tkinter и модулях `backend/`. Прежний Python API также сохранён. Python может быть полноценным backend; невозможности использовать его нет.

**Что делает класс?** `SobranoApp` объединяет состояние окна (`self.parts`, поля, подписи) и методы обработки действий. `self` — конкретный экземпляр этого окна.

**Где цикл/условие?** `refresh()` перебирает категории и отбирает кандидатов; `choose()` проверяет индекс `if`, затем удаляет или записывает деталь в словарь и вызывает пересчёт.

**Где база?** Локально это файл `instance/sobrano.sqlite`, который открывает `online/node-db.mjs`. SQL-команды сосредоточены в `online/store.mjs`. Исходный JSON каталога и SQL-база — разные уровни хранения.

**Чем SQL отличается от localStorage?** SQL хранится на сервере и позволяет получить сохранённые сборки после входа с другого браузера к тому же серверу. localStorage содержит только избранное, сравнение и несохранённый выбор конкретного браузера.

**Как устроена авторизация?** При регистрации сервер создаёт хеш пароля с солью. При входе проверяет пароль и выдаёт сессию через HttpOnly-cookie. Право изменения сборки определяется на сервере, а не скрытием кнопки в HTML.

**Можно прочитать чужую сборку?** По общей ссылке — да. Изменять и удалять оригинал может только её владелец. Получатель может сохранить свою копию.

**Зачем CSRF?** Чтобы чужая страница не могла незаметно отправить изменение от имени вошедшего пользователя только за счёт его cookie.

**Что защищает SQL-запросы?** Значения передаются параметрами, а не склеиваются с SQL-текстом. До SQL проверяются поля и типы. Это отдельная защита от проверки формы в браузере.

**Почему нет администратора магазина?** Проект подбирает детали и хранит пользовательские составы. Заказов, продаж и управления магазином в его назначении нет. Админка для этого сценария не требуется и не заявляется.

**Что показывает Network?** Адрес, метод, HTTP-статус и JSON. 200 — успешный расчёт, 201 — новая сохранённая запись, 400 — неверный запрос. Остальные коды объясняются в [ONLINE_BACKEND.md](ONLINE_BACKEND.md).

**Сайт работает без Интернета?** Локальный сервер, каталог, шрифты и расчёт могут работать без Интернета. Внешние фотографии без локального кеша могут не загрузиться. Для сайта нужен работающий локальный процесс, даже если браузер уже открыт.

**Все компоненты гарантированно совместимы?** Скрываются известные конфликты по данным каталога. Неизвестный параметр не превращается в гарантию; BIOS, точные разъёмы и исполнения моделей проверяются не полностью.

**Все цены актуальные?** Нет. Есть датированные магазинные предложения и отдельно подписанные расчётные цены. Автоматический сбор цен не реализован.

**Что ещё улучшить?** Проверяемые локальные фото, регулярное получение цен по разрешённым источникам, больше характеристик совместимости, восстановление доступа к аккаунту и дополнительные ограничения для массового публичного сервиса.

## Что не следует заявлять

Не называйте статический GitHub Pages сервером Node.js, localStorage — серверной базой, расчётные цены — актуальными предложениями магазина, а локальный тест — проверкой публичного адреса. Не обещайте абсолютную совместимость, отсутствие любых ошибок, оплату, доставку или административные возможности, которых нет.
