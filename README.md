# СОБРАНО

Учебный каталог компьютерных комплектующих и сборок ПК для Казахстана: 190 моделей, 8 категорий и 22 готовые конфигурации. Русский интерфейс, цены в тенге, светлая и тёмная темы, адаптивная вёрстка.

Есть две отдельные части: **фронтенд — HTML, CSS и JavaScript**, **бэкенд — Python**. В локальном режиме Python выполняет поиск, фильтрацию, подбор совместимых компонентов и расчёт бюджета. GitHub Pages использует статические JSON и клиентские правила.

Сайт: **https://china1602-glitch.github.io/sobrano/**. Репозиторий: https://github.com/china1602-glitch/sobrano.

Карта исходников — [PROJECT_STRUCTURE.md](PROJECT_STRUCTURE.md), публикация и проверка Pages — [docs/PUBLICATION.md](docs/PUBLICATION.md).

## Быстрый запуск в Windows и VS Code

Откройте в VS Code именно папку `github/`, где лежат `server.py` и `index.html`. Выберите **Terminal → New Terminal**. Из общей рабочей папки:

```powershell
cd "$HOME\sobrano-work\github"
python server.py
```

Откройте **http://127.0.0.1:8080/**. Терминал оставьте открытым. Остановка — **Ctrl+C**.

Если работает команда `py`, можно использовать `py server.py`. Если порт занят: `python server.py --port 8081`, затем http://127.0.0.1:8081/. На этом компьютере проверен Python 3.13.14. Используется только стандартная библиотека, установка пакетов через pip/npm не нужна. Если Python отсутствует на другом компьютере, сначала потребуется его бесплатная установка.

F5: установите бесплатные расширения Microsoft Python и Python Debugger, выберите **Python: Select Interpreter**, затем конфигурацию **«СОБРАНО: запустить Python-сервер»**. Во время отладки браузер ждёт API без тайм-аута. Обычный запуск сохраняет тайм-аут. Настройки находятся в `.vscode/launch.json`. Через **Terminal → Run Task** также доступны запуск API, статического режима и проверки.

Не открывайте HTML двойным щелчком: загрузке JSON нужен HTTP. Обычный статический сервер не демонстрирует обработчики Python API.

## Статический режим без бэкенда

Для локальной проверки того же режима, который используется на GitHub Pages:

```powershell
cd "$HOME\sobrano-work\github"
python -B -m http.server 8000 --bind 127.0.0.1
```

Откройте **http://127.0.0.1:8000/**. Здесь Python только раздаёт файлы; API проекта не выполняется. Можно использовать установленный VS Code Live Server вместо этой команды.

Файл `runtime.json` в репозитории содержит `{"backend":"static"}`. Локальный `server.py` возвращает по адресу `/runtime.json` режим `python`, не меняя файл на диске. Переключать настройки вручную не требуется.

GitHub Pages публикует содержимое `github/` как корень сайта из выбранной ветки, **/(root)**. Статический режим проверен локально и в подпапке проекта. Статус последнего развёртывания проверяется в GitHub Actions; подробные шаги приведены в [docs/PUBLICATION.md](docs/PUBLICATION.md).

## Возможности

- Каталог: поиск по всем словам и характеристикам, категории, бренд, диапазон цены, характеристики категории, сортировка, список/плитка, загрузка следующих товаров.
- Карточки моделей: характеристики, тип цены, дата и источник предложения, подписи к изображениям.
- Избранное и сравнение до четырёх моделей одной категории; режим «Только отличия».
- Готовые сборки: подбор по назначению и бюджету, подробный состав, перенос в конфигуратор.
- Конфигуратор: произвольный порядок выбора, исключение известных конфликтов, бюджет, предупреждения о неизвестных данных, ссылка на состав и экспорт TXT.
- Выбор сохраняется в localStorage браузера и синхронизируется между вкладками одного адреса.
- Ошибки загрузки и API показываются явно. При отказе изменения состава предыдущий состав сохраняется.

## Python API

| Метод и адрес | Результат |
| --- | --- |
| GET /api/health | Диагностика процесса и количество данных |
| GET /api/catalog | Каталог, предложения, цены и результаты готовых сборок |
| GET /api/products?cat=cpu&search=Ryzen&sort=asc | Отобранные и отсортированные идентификаторы моделей |
| GET /api/builds?budget=500000 | Идентификаторы подходящих сборок |
| POST /api/configuration | Проверка выбранного состава, бюджет и оценка всех кандидатов |

В F12 → Network → Fetch/XHR видны запросы и ответы. Доказательный пример: выбрать RTX 4090, затем увидеть исключение DeepCool PK550D 550 Вт.

```powershell
$result = Invoke-RestMethod -Uri "http://127.0.0.1:8080/api/configuration" -Method Post -ContentType "application/json" -Body '{"parts":{"gpu":85}}'
$result.assessments.p40 | ConvertTo-Json -Depth 5
```

`allowed: false` — результат Python. Товар p85 — RTX 4090, p40 — PK550D в сохранённом каталоге. Порядок строк JSON нельзя менять без переноса ссылок, сборок и предложений.

## Данные и ограничения

Сохранены исходные модели, характеристики и предложения обеих копий; они совпадали. Каталог не является магазином. Цены без подходящего источника подписаны как учебные расчётные оценки. В JSON сохранены 8 снимков для 7 моделей; снимки старше 30 дней остаются в истории и не участвуют в бюджете. Наличие не выдумывается, автоматического обновления цен нет.

Для 189 моделей есть внешнее изображение: 93 точных, 96 подписанных примеров линейки/исполнения. Для Ryzen 7 5700X3D OEM используется честная заглушка. Внешние фото требуют Интернета; при ошибке загрузки отображается сообщение. Интерфейс, данные и шрифты доступны локально. Источники: [цены](docs/PRICE-SOURCES.md), [фото](docs/PHOTO-SOURCES.md).

Совместимость проверяется по известным параметрам: сокет, память, основные размеры, форм-фактор и оценка питания. Неизвестные данные дают предупреждение. BIOS, QVL, разъёмы, охлаждение и фактические зазоры требуют отдельной проверки; [подробности правил](docs/COMPATIBILITY.md).

Нет учётных записей, заказов, платежей и серверного хранения личных сборок. Выбор хранится в браузере; ссылка и TXT позволяют передать состав. SQL для этого учебного объёма не требуется.

## Проверки

```powershell
python -B -m unittest discover -s tests
node --test tests/*.test.cjs
node tests/browser-smoke.cjs
```

Node.js нужен только для JavaScript- и браузерных проверок. Браузерный тест использует установленный Chrome и стандартные модули Node.js 22+; дополнительных npm-пакетов нет. При другом расположении Chrome задайте `$env:CHROME_PATH`. Тест запускает временные серверы на 18080/18081 и Chrome без окна, проверяет оба режима, затем останавливает запущенные процессы. Эти порты должны быть свободны. Для обновления контрольных скриншотов перед тестом задайте `$env:SOBRANO_SCREENSHOTS='1'`.

Результаты текущей проверки и сравнения копий — [docs/FINAL_REPORT.md](docs/FINAL_REPORT.md). Старые результаты сохранены отдельно в [docs/QA.md](docs/QA.md).

## Обновление GitHub Pages

Публикация настроена на main, /(root). Изменения готовятся и проверяются в finish/sobrano-defense, затем безопасно объединяются в main и отправляются обычным push без force. Резервная local/ находится вне репозитория и не меняется.

Перед отправкой проверьте git status, git diff и актуальную origin/main. При конфликтах остановитесь. После push дождитесь успешного pages build and deployment и проверьте публичный сайт. Пошаговые действия — [docs/PUBLICATION.md](docs/PUBLICATION.md).

Опубликованный сайт использует static; исходный Python-бэкенд сохраняется для локальной демонстрации. Скрипты запуска, платные сервисы и установка пакетов на хостинг не требуются.
