# СОБРАНО

Независимый учебный информационный каталог компьютерных комплектующих для Казахстана. Русский интерфейс, цены в тенге. Сайт не продаёт товары и не принимает оплату.

## Запуск на своём компьютере

Откройте папку проекта в VS Code. В нижнем терминале Windows выполните:

```powershell
py server.py
```

Откройте http://127.0.0.1:8080/ . В терминале видны реальные HTTP-запросы браузера. Диагностика работающего Python-сервера: http://127.0.0.1:8080/api/health . Сервер работает, пока открыт терминал. Остановка — Ctrl+C. Никакой установки Python-пакетов, npm-пакетов или платных сервисов для самого сайта не требуется.

Для запуска клавишей **F5** установите в VS Code бесплатные расширения **Python** и **Python Debugger** от Microsoft, выберите интерпретатор через `Python: Select Interpreter`, затем конфигурацию «СОБРАНО: запустить Python-сервер». Настройки находятся в `.vscode/launch.json`. Одновременно нужен только один сервер на порту 8080.

Python обслуживает HTTP-запросы и диагностический API. Интерфейс, фильтры и совместимость выполняются на JavaScript в браузере. Это сайт с Python-сервером и HTML/CSS/JavaScript-интерфейсом; утверждать, что весь проект написан на Python, неверно. Пошаговая подготовка и объяснение для защиты — [docs/DEFENSE.md](docs/DEFENSE.md).

Для GitHub Pages источник публикации — ветка с готовыми файлами, папка `/ (root)`. Все внутренние пути относительные, поэтому проект работает и в подпапке `/sobrano/`. GitHub Pages отдаёт статические файлы и не запускает Python: `server.py` и `/api/health` используются при локальном запуске.

## Обновление готовых файлов

1. Остановите локальный сервер сочетанием Ctrl+C и сохраните открытые файлы в VS Code.
2. Сохраните прежнюю папку целиком, например под именем `sobrano-backup-2026-10-20`. Это резервная копия ваших правок и добавленных файлов.
3. Скачайте ZIP текущей ветки GitHub и распакуйте его в отдельную чистую папку. Откройте в VS Code папку, в которой непосредственно лежит `index.html`.
4. Сохраните структуру каталогов: `css/`, `js/`, `assets/`, `docs/` и `tests/` переносятся целиком. Например, `app.js` остаётся внутри `js/`, а `style.css` — внутри `css/`.
5. При загрузке на GitHub переносите содержимое папки проекта вместе с папками. В корне репозитория должны находиться `index.html` и остальные страницы, а скрипты, стили и шрифты — в своих каталогах.

Повторная загрузка отдельных файлов из всех подпапок в корень создаёт неиспользуемые дубли. Такие копии удалены после сравнения с рабочими файлами; содержимое правильных папок сохранено. Новый ZIP лучше распаковывать в чистую папку, чтобы старые лишние файлы не оставались после обновления.

Все девять HTML-страниц нужны: `index.html`, `catalog.html`, `product.html`, `builds.html`, `build.html`, `builder.html`, `favorites.html`, `compare.html` и `about.html`. В частности, `builds.html` показывает список сборок, а `build.html` — состав одной сборки. Очистка данных браузера для обновления файлов не требуется.

Серверной базы данных нет: избранное, сравнение и текущая конфигурация хранятся в браузере. Старый ключ сохранения `sobrano:diploma:1` сохранён для совместимости с предыдущей версией.

## Цены и ограничения

В наборе сохранены **8 снимков предложений для 7 моделей**. Все они помечены как `web-snapshot`: получены из доступного представления страниц магазина, в том числе поискового кэша. Это не поток актуальных цен. Указаны магазин, ссылка, дата фиксации и условия. Наличие отмечено только там, где оно было прямо указано на снимке. Подробности — [docs/PRICE-SOURCES.md](docs/PRICE-SOURCES.md).

Остальные цены — учебные расчётные оценки. Оценка бюджета использует минимальную зафиксированную цену не старше 30 дней, если товар не был помечен отсутствующим. Для остальных моделей применяется расчётная оценка. Тип цены виден в карточке и составе сборки. Доставка, ОС, периферия и работа сборщика в сумму не входят.

Новые цены **не загружаются автоматически**. Для обновления нужно проверить страницу магазина и изменить соответствующую запись в `js/offers.js`, сохранив дату, ссылку и точное соответствие модели. Нельзя обновлять только дату старого снимка.

Изображения есть для 189 из 190 моделей: 93 точных фотографии и 96 подписанных примеров соответствующей линейки или исполнения. Для AMD Ryzen 7 5700X3D OEM пока оставлена заглушка: маркировка доступного изображения не подтверждена. Источники и лицензии — [docs/PHOTO-SOURCES.md](docs/PHOTO-SOURCES.md). Изображения требуют Интернета; шрифт и интерфейс загружаются локально.

В каталоге по умолчанию включён фильтр «Подходят к моей сборке». В конфигураторе списки обновляются после каждого выбора, в том числе GPU → БП и БП → GPU. Модель заменяет старую деталь той же категории; прочие сохранённые детали учитываются. Неизвестные мощность и размеры не считаются нулями: конфигуратор сообщает о недостатке данных. Модели с неполными данными остаются доступными без повторяющихся подписей; недостающие характеристики перечислены в общем результате проверки сборки. Расчёт БП учитывает рекомендацию видеокарты и запас мощности; это ориентир, а не измеренное потребление. Проверка не заменяет сверку BIOS, QVL, разъёмов, креплений и фактической геометрии деталей. Подробности — [docs/COMPATIBILITY.md](docs/COMPATIBILITY.md).

## Проверки

Проверка HTTP-сервера стандартными средствами Python:

```powershell
py -m unittest discover -s tests -p "test_*.py" -v
```

Для модульных проверок интерфейса нужен Node.js; серверу сайта он не требуется:

```sh
node --test tests/*.test.cjs
```

При изменении набора данных нельзя переставлять строки товаров: сохранённые ссылки используют стабильные номера `pN`, а составы — номера строк. Новые товары добавляются в конец. Для произвольной перестановки нужна отдельная миграция идентификаторов.
