# Защита «СОБРАНО» по ПМ 6

План рассчитан примерно на **5 минут 45 секунд** и следует переданным вопросам ПМ 6. Не заучивайте весь текст: запустите проект и проследите действия в коде. Результаты выполненных проверок берите из [docs/ONLINE_CHECKS.md](docs/ONLINE_CHECKS.md).

## Подготовка до выступления

1. В VS Code откройте папку с `package.json` и `online/`. В терминале: `node online/server.mjs`.
2. Откройте **http://localhost:8080/**. Используйте этот же адрес в течение всего показа.
3. Во втором терминале: `py desktop_app.py`. Подготовьте Python-окно с готовой сборкой.
4. Зарегистрируйте учебный аккаунт через сайт заранее. Пароль не выводите на слайд и не сохраняйте в исходники.
5. Откройте DevTools (F12) → Network → Fetch/XHR. Для показа входа с другого клиента подготовьте другой браузер/приватное окно.
6. В редакторе приготовьте `desktop_app.py`, `js/backend-client.js`, `online/api.mjs`, `online/domain.mjs`, `online/store.mjs`, `online/auth.mjs`.
7. Сделайте снимки запущенного Python-окна, сайта, мобильной ширины, успешной операции и неверного ввода для слайдов. Эти материалы прямо указаны в задании.

Не запускайте одновременно старый Python API и новый Node-сервер на порту 8080. Не заменяйте основной запуск простым `http.server`: у него нет аккаунтов и SQL API.

## Небольшой фрагмент Python

В `desktop_app.py` откройте метод `choose()`. Его смысл по шагам:

1. `current()` получает выбранную строку списка.
2. Проверка `if` отсеивает недопустимый индекс.
3. `self.options` связывает строку списка с индексом компонента каталога.
4. Если выбрана пустая строка, `pop()` убирает деталь; иначе она записывается в словарь `self.parts`.
5. `self.dirty = True` отмечает несохранённое изменение.
6. `self.refresh()` пересчитывает бюджет и варианты выбора.

`SobranoApp` — класс окна; `self` означает его экземпляр. Методы — функции этого класса. Tkinter/ttk создают кнопки, подписи и списки; `filedialog` выбирает путь, `messagebox` показывает сообщения. `backend/compatibility.py` и `backend/pricing.py` содержат Python-расчёт. Новый сервер сайта исполняет JavaScript-модули, а не этот Python-код.

## Один запрос для пояснения

Во втором PowerShell-терминале, пока сервер запущен:

```powershell
$base = 'http://localhost:8080'
Invoke-RestMethod "$base/api/health"
$r = Invoke-RestMethod -Uri "$base/api/configuration" -Method Post -ContentType 'application/json; charset=utf-8' -Body '{"parts":{"gpu":85}}'
$r.assessments.p40 | ConvertTo-Json -Depth 5
```

В текущем каталоге p85 — RTX 4090, p40 — БП DeepCool PK550D 550 Вт. Ответ `allowed: false` показывает серверное правило мощности. Не объясняйте его как доказательство проверки всех возможных деталей и исполнений.

Для некорректного запроса можно использовать Windows curl:

```powershell
Invoke-RestMethod -Uri "$base/api/configuration" -Method Post -ContentType 'application/json; charset=utf-8' -Body '{"parts":{"gpu":99999}}'
```

Ожидается HTTP 400 с JSON-ошибкой; PowerShell выведет ошибку запроса. Это намеренный пример недопустимого ввода, а не успешная операция. Тот же ответ можно показать в Network браузера.

## Готовые короткие объяснения

**Как всё связано:** «Браузер вызывает `fetch`. Обработчик в `online/api.mjs` проверяет запрос. Для расчёта он обращается к `domain.mjs`, для хранения — к `store.mjs`. Сервер возвращает JSON, интерфейс обновляет DOM».

**Почему это настоящий backend:** «Расчёт и запись выполняются отдельным серверным процессом. При остановке Node.js API становится недоступным. Перезапуск не удаляет SQLite. Другой браузер после входа получает данные из той же базы».

**Как защищён пароль:** «В базе хранится производный хеш PBKDF2 с индивидуальной солью, а не открытый пароль. Сессию браузер передаёт через HttpOnly-cookie. Вход проверяется на сервере».

**Почему JavaScript на сервере:** «Node.js исполняет JavaScript вне браузера. Выбор сделан для текущей локальной/облачной архитектуры. На Python также возможно написать backend; в проекте сохранены Python API и отдельное приложение».

**Что проверялось:** «Назову только выполненные тесты из актуального отчёта: расчёт, реальные HTTP-запросы, SQLite, ошибки и права, браузерные сценарии. Ручную проверку моей Windows-копии покажу отдельно».

**Почему нет админки:** «Сервис подбирает комплектующие и хранит составы пользователей. Продаж и заявок магазина нет. Аккаунт управляет своими сборками; административные функции не заявляются».
